QuestionHow should the product limit scripted abuse of the anonymous token and lead functions on free plans?
Why youIt sets what protects the Gemini key quota and the server validation, both high-criticality requirements, and it accepts a residual risk only the owner can accept.
OptionsWAF rate limit, same-origin and accepted residual risk: One Vercel Firewall rate limiting rule (Fixed Window, answers 429) on /api/* is available on Hobby, with no code and no data store.; Neither function sends Access-Control-Allow-Origin *, so other sites cannot call them from a visitor's browser.; but A distributed attack from many addresses still passes a per-IP limit.; Rate limiting is usage-priced; on Hobby, which is never billed, exhausting its included usage may suspend the rule until the window resets.. Or Application-level rate limit with a shared store: Per-client limits independent of the WAF usage allowance.; but Adds a store (for example Redis) the approved stack does not have.; Still per-IP, so it does not stop a distributed attack either.. Or CAPTCHA or proof of work before each call: Raises the cost of every scripted call, distributed or not.; but Adds a provider, friction and visitor signals sent to a third party..

  1. WAF rate limit, same-origin and accepted residual risk
  2. Application-level rate limit with a shared store
  3. CAPTCHA or proof of work before each call
